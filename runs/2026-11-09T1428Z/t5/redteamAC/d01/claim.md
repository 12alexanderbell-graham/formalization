# d01 – parse differential: Python splitlines vs Lean readLines (hidden phrase text)

Generated line (CLAIMS.md, every claim that reaches `IsCriticalIsotherm`, e.g. the premises at CLAIMS.md l.3918, 3990, 4018):
"the isotherm pressure function of molar volume `p := ...` satisfies the critical point condition of an isotherm with the molar volume at the point `v` (pressure as a function of molar volume at fixed temperature; first and second volume derivatives of pressure both vanish; a mere stationary point is not critical)<U+000B> (a horizontal inflection point of the isotherm); by definition, means ..."

False/overstated: the Lean body is `deriv p v = 0 ∧ deriv^2 p v = 0` (two vanishing derivatives). That does not make v an inflection point (p = (v-v0)^4 has a minimum there, and the blind reader's own line "a horizontal inflection point of the isotherm" sits in phrase_clause_baseline.txt with reason (6): not implied by two vanishing derivatives). A reader of the generated text is told the condition IS a horizontal inflection point; the gloss is placed after the clause list and reads as one more property of the definition.

Mechanism: the added text is separated from the checked phrase by U+000B. `check_claims.parse_phrases` uses `str.splitlines()`, which ends a line at U+000B (also U+000C, U+001C-1E, U+0085, U+2028/9); the rest is a separate "line" without " | ", so it is skipped. `Claims.lean` `readLines` splits on "\n" only, so the phrase in CLAIMS.md contains the whole text. U+000B is < 0x20, so Lean's JSON escaping writes it as \u000b and `.lake/phrases.jsonl` stays one line per entry; P2 (spec_vocabulary) and the glossary run on the full phrase and pass: the words horizontal/inflection are in CriticalSpec's field docstring (spec_text), the others in the registry texts. The phrase as parsed by check_claims is IDENTICAL to the old one, so `--base` sees no changed phrase and needs no LEDGER line; no registry line changes.

Rules passed (run on a copy): duplicate_phrases, formula_in_phrase, load_registry, role_binding (P3/P4/P6), coverage (P7), registry_complete (P8/P9), approximate U2/glossary, P2 for the added words, `registry_removals`/baseline growth/changed-phrase (`--base` parts, checked against the base copy), `_controls()`. Not run: Lean (CLAIMS.md regeneration) and the other CI scripts that read CLAIMS.md (a splitlines() over CLAIMS.md would cut the claim line at U+000B; if one of them rejects that, the defect is caught there).

P10/P11: survives P10 (no shape involved). Survives P11 if the comparison of the phrase file with the generated output goes through `parse_phrases` (dict compare) or any splitlines(); it is caught only if P11 compares raw bytes/lines split on "\n". Any hidden text built from the definition's own words is possible, this one is the sharpest from the stock vocabulary.
